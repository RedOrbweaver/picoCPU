## picoPAL - An rp2350-based retro game console

The console is made out of three pi pico boards:
- CPU, a pi pico 2 W - processes game logic, receives bluetooth inputs, and generates audio
- GPU, a pi pico 2 - rasterizes entities as commanded by the CPU and generates a PAL signal. See https://github.com/RedOrbweaver/picoGPU
- Controller, a pi pico W - housed on a separate board, detects button presses and sends them over bluetooth. See https://github.com/RedOrbweaver/picoCONTROLLER

https://github.com/user-attachments/assets/fa2e2646-0e4b-4844-b82e-a5d33f70e0dd

## GPU

The PAL output has a full 8-bit output range from 0.3V to 1V, using a pin to add 0.3V to the output when sending lines, which is possible thanks to the amplifier configuration.

Rendering involves up to 256 entitites, a geometry buffer, used by entities like multiline, multipoint and multisprite, and a variable size texture buffer used by sprites.

Core 0 is tasked with rasterization and communication with the CPU, while Core 1 generates the PAL signal.

## CPU

Core 0 communicates with the GPU and runs game logic, while Core 1 generates audio.

An abstraction layer manages entities as well as the texture and geometry buffer.

## The main board

![IMG_20250913_114254801_BURST001](https://github.com/user-attachments/assets/7c94bb18-aca4-42a6-bfc6-b7db88151595)

The main board runs off of 5V input, which it uses to power the boards as well as generate 3.3V and -3.3V inputs for the amplifiers. 

Note that my test board has been through several design changes. Initially the negative rail was generated by an MC34063 chip, however even with several LC filters, the noise was still visible, nessessitating switching to an ICL7660. 
Similarly, the amplifiers I had initially used were not up to the task, and so I ended up using a pair of OPA1612 opamp pairs, which were retrofited using rather hacky conversion boards.

## Compilation

All projects use CMAKE and are configured to run in VSCODE using the Raspberry pi pico extension.

Compiling picoCPU requires a shared header from the picoGPU repo, which must be made accessible under ../picoGPU/shared.hpp. Simply having the repos in the same folder should suffice.
